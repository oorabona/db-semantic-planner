# Admission-layer obligation table — managed-state ledger delivery 2

Status: ACTIVE. 53 of 67 rows are held with resolving citations; the fourteen rows
still marked `hold`/`rebuild` have their remaining constructions specified in #503
(operator-deferred, 2026-08-15). The final review reads those rows as known,
already-triaged bounds.

This table is the definition of done for the admission-layer rebuild (#499). One row per
obligation: the property that must hold, the attack that must be refused, and the
public-surface test that constructs the attack and demands the refusal. **A check without
its green refusing test does not ship.** The single final adversarial review reads the
rebuilt code against this table and the ADR 0006 threat model, nothing else.

Row IDs (`OBL-*`) are permanent identifiers for this document and may be referenced from
tests and issues. File:line anchors refer to `feat/481-delivery-2@9182004c`, the state
being rebuilt; they name where the current check lives, not where the rebuilt one must.

## Actor model and bounds

In scope (ADR 0006 §Threat model): cooperating deployment roles using dbsp through its
public surfaces — the package root exports of `@dbsp/core` and `@dbsp/adapter-pgsql`, and
the CLI. The declared guarantee is: *the admitted-execution façade rejects fabricated
in-process inputs at its boundary*. Every obligation below is an instance of that
sentence, plus the detection guarantees (external DDL, restored snapshots, crashes, lost
COMMIT acknowledgements).

Out of bounds — findings against these do not block, per the ADR's declared non-goals:

- A superuser or table owner racing name resolution: detected post hoc by identity and
  read-back checks, never prevented.
- Code importing the `/internal` subpaths: trusted by declaration (their headers say so).
  The public façade, not the escape hatch, carries the refusal obligations. The one
  obligation the escape hatch does carry is documentation consistency (OBL-CLI6).
- Advisory locks against non-cooperating PostgreSQL clients: they bind dbsp processes
  only; the external-DDL window of a non-transactional segment is covered by the run's
  accepted `external-ddl-exclusion` assumption, a stated bound.
- SQL-text-to-address correctness at send time: the binding is established once, at
  admission, by byte-exact manifest⇄plan bundle comparison (OBL-AUTH4); the send path
  does not re-parse SQL to re-verify which address it targets. This is a declared bound,
  not a gap: re-verification would need a SQL parser and would re-open the class.
- Operator per-address acceptance is a destructive-only property by design: ordinary DDL
  is gated by assumption acceptance (OBL-RUN4), not per-address grants.

## Design constraints for the rebuild

These are not obligations rows; they are operator-decided constraints the rebuilt design
must satisfy (#501, #499):

1. **Single-owner session lifecycle.** One session owns an admitted execution's DDL and
   the read-back that observes it. No step of one admitted execution may wait on
   catalogue locks held uncommitted by another session of the same execution (the
   deadlock construction in #501). The façade shape (one entry point) is kept. The
   per-lifecycle session/transaction matrix in the appendix makes this concrete; the
   rebuild design confirms or amends that matrix explicitly, never implicitly.
2. **Catalogue-reads-only validation.** Physical-shape validation must not require
   `CREATE SCHEMA` (no scratch-schema DDL). Validation compares catalogue reads against
   a **versioned reference specification** enumerating every validated artefact: columns
   (name, type, nullability), constraints with canonical expression text, triggers and
   their functions, indexes, defaults. What the specification does not represent is not
   claimed validated — the scratch-schema byte comparison proved "the server's own DDL
   expansion of the reference", and that stronger, implicit claim is deliberately
   narrowed to the specification's explicit one. Pair discovery performs no DDL per
   candidate. ONE declarative, versioned ledger specification generates BOTH the DDL
   renderers and the validator's expected-facts manifest, so the two cannot diverge
   silently; a real-server matrix test asserts the initialized ledger's complete
   catalogue projection equals the manifest. Expression-bearing artefacts (CHECK
   expressions, defaults) compare against per-major captured deparse fixtures — captured
   from a real server, never written from memory; everything else compares structural
   catalogue facts; dbsp-authored function bodies compare verbatim `prosrc`. Executable
   obligation: OBL-AUTH11.
3. **Fabrication is inexpressible where possible.** Where an obligation says "cannot be
   constructed", prefer a constructor whose required evidence parameter makes the
   omission fail to compile over a runtime check (the one instruction of this project's
   review history that no later round attacked).
4. **No new recovery mechanism.** The 14-event grammar is closed; refusal/ambiguity
   classes exist; every rebuilt path reuses them.

## How to read the columns

- **Obligation** — the property, mechanism-free where possible.
- **Attack to refuse** — a concrete construction, through a public surface, by an actor
  in the model. "Refuse" means the documented typed refusal/exit path, never a hang, a
  silent skip, or an untyped throw presented as success.
- **Refusal test** — where the test lives (or will live) and the surface it drives.
  `e2e` = real-PostgreSQL harness (failpoints available), `unit` = package unit suite,
  `docs` = executable-docs suite. A row's status flips to *held* only when its test is
  green AND has been seen red (mutation-articulated).
- **Status** — `rebuild (#N)`: current code fails this row, inventory issue N.
  `hold`: current code appears to satisfy it; the rebuild must keep it and add the
  refusal test. `bound`: declared bound, documented, no runtime test.

Three conventions the columns rely on:

- **Evidence type.** Where the obligation is a refusal, the test is a refusal
  construction. A few rows owe different evidence — a resource-bound property, an audit
  inventory, a docs run — and say so; their definition of done is that named evidence
  green, not a refusal test. There are no unlabelled exceptions.
- **Attack provenance.** An attack marked *harness corruption* uses direct SQL to
  corrupt storage — that is the test rig simulating tamper/crash debris, not the
  in-model caller. The REFUSAL it demands must still surface through a public reading or
  mutating surface.
- **Held-proof audit trail.** `hold` is provisional. A row becomes **held** only when
  its test cell carries the test identifier and the mutation that was observed red; the
  final review treats a `hold` without that witness as unproven, not as satisfied.
- **Public surface first.** Every row whose attack is an in-model fabrication must have
  a refusal test through a package-root export or the CLI; internal-seam tests are
  allowed as additional focused evidence, never as the row's only test. The exceptions
  are the rows labelled harness-corruption/backstop or audit-evidence, per the
  conventions above.

## Appendix — session and transaction shape per lifecycle

Design constraint 1 made concrete. This matrix is a DESIGN DECISION the rebuild's spec
confirms or amends explicitly (with its consult on record) before any code; every
lifecycle names one owning backend, and OBL-LOCK1's PID assertions test exactly this
table.

| Lifecycle | Backend | Transactions |
|-----------|---------|--------------|
| Transactional DDL | one | the ATOMIC SEGMENT is the transaction unit: claim + DDL + resolution of the steps sharing a segment ride that segment's ONE transaction and share its fate (plan INV-07); a step whose outcome must survive a later step's failure is, by that requirement, its own segment with its own transaction — never a shared transaction with a side channel |
| Non-transactional DDL | one (same session throughout) | claim commit → `executing` commit → DDL (autocommit) → terminal commit; separate transactions, one backend |
| Paired readdress | one | pair claims, DDL, read-backs, resolutions per its protocol; a crash leaves the open pair (OBL-REC13) |
| Adoption | one | claim + under-lock verification + resolution in one transaction |
| Recovery / reconcile | one per run | locks + classification + appends: one transaction per decision |

The independent outcome session of the current implementation is retired by this matrix.
What it protected — a terminal surviving an outer rollback — is provided by segmentation
instead: outcomes share their segment's fate by design, and durability across segments
comes from segment boundaries, never from a second session committing behind the
segment's back. If the rebuild's spec finds a lifecycle this matrix cannot serve, the
matrix is amended here first, with its consult on record.
