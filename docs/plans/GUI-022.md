# GUI-022: Project Mode — Specification

> **Status:** canonical (implemented 2026-02-17, 10 blocks, 934 tests, reviewed YES)
> **Brief:** `docs/briefs/gui-project-mode.md`
> **Branch:** `feat/gui-project-mode`

## 1. Overview

Transform the GUI from a stateless single-session explorer into a project-aware application with persistent storage per project, a project creation wizard, schema.ts editing, and reorganized file menu.

### Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Project marker | `dbsp.settings.json` at project root | Existing pattern, no migration needed |
| SQLite location | `$APPCONFIG/projects/<name>/data.sqlite` | Tauri-managed, invisible to user, no .gitignore needed |
| Project ID | Raw normalized absolute path | No over-engineering; path is unique by definition; special chars sanitized for folder name |
| Storage folder | `$APPCONFIG/projects/<custom-name>/` | Uses the project name from wizard (filesystem-safe slug); human-readable in file explorer |
| Ad-hoc storage | `$APPCONFIG/default/data.sqlite` | Standalone mode has persistent storage too |
| App-level data | `$APPCONFIG/app.sqlite` | Recent projects list, global app logs |
| Credentials | NEVER stored in plain text | Passwords: `env://VAR` reference or prompt-on-connect; NEVER in schema.ts, NEVER in SQLite, NEVER plain text in dbsp.settings.json |
| Path normalization | `path.resolve()` + lowercase on Windows | Ensures same folder = same project identity regardless of casing or trailing slashes |
| Single instance | Tauri default single-instance | No SQLite lock contention between processes |

### Storage Map

```
$APPCONFIG/
├── app.sqlite                          ← Global (recent projects, app logs)
├── default/
│   └── data.sqlite                     ← Standalone mode (history, IPC logs)
└── projects/
    ├── my-app/
    │   └── data.sqlite                 ← Project "my-app" (history, IPC logs, connection profiles)
    └── backend/
        └── data.sqlite                 ← Project "backend" (history, IPC logs, connection profiles)
```

### SQLite Schemas

#### app.sqlite (global)

```sql
CREATE TABLE _meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
-- Keys: 'schema_version' (for future app.sqlite migrations)

CREATE TABLE recent_projects (
  path TEXT PRIMARY KEY,            -- Normalized absolute path (unique ID)
  name TEXT NOT NULL,               -- Display name (custom project name)
  folder_name TEXT NOT NULL,        -- Filesystem-safe slug used in $APPCONFIG/projects/<folder_name>/
  last_opened_at INTEGER NOT NULL,  -- Unix timestamp ms
  created_at INTEGER NOT NULL
);

CREATE TABLE app_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  level TEXT NOT NULL,
  source TEXT NOT NULL,
  message TEXT NOT NULL,
  duration_ms INTEGER
);
CREATE INDEX idx_app_logs_ts ON app_logs(timestamp);
```

#### data.sqlite (per-project or default)

```sql
CREATE TABLE _meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
-- Keys: 'project_path' (normalized abs path), 'project_name', 'schema_version', 'migration_complete'

CREATE TABLE query_history (
  id TEXT PRIMARY KEY,              -- UUID
  query TEXT NOT NULL,
  language TEXT NOT NULL,           -- 'sql' | 'nql'
  database TEXT,                    -- Connection database name
  connection_id TEXT,               -- FK to connection_profiles.id (nullable for ad-hoc)
  timestamp INTEGER NOT NULL,
  duration_ms INTEGER,
  row_count INTEGER,
  success INTEGER NOT NULL DEFAULT 1,
  error TEXT
);
CREATE INDEX idx_history_ts ON query_history(timestamp);
CREATE INDEX idx_history_lang ON query_history(language, timestamp);

CREATE TABLE ipc_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  level TEXT NOT NULL,
  source TEXT NOT NULL,             -- Always 'ipc' but kept for consistency
  message TEXT NOT NULL,
  duration_ms INTEGER,
  method TEXT,                      -- IPC method name
  connection_id TEXT                -- Which connection this relates to
);
CREATE INDEX idx_ipc_ts ON ipc_logs(timestamp);

CREATE TABLE connection_profiles (
  id TEXT PRIMARY KEY,              -- UUID
  name TEXT NOT NULL,               -- Display name (e.g. "local dev", "staging")
  environment TEXT,                 -- Logical env label (defaults to name; e.g. "dev", "staging", "prod")
  type TEXT NOT NULL DEFAULT 'postgresql',  -- DB engine discriminant (future: mysql, sqlite, etc.)
  config TEXT NOT NULL,             -- JSON blob with engine-specific settings (host, port, database, etc.)
  color TEXT,
  created_at INTEGER NOT NULL,
  last_used_at INTEGER
);
-- config JSON for type='postgresql': {"host":"…","port":5432,"database":"…","username":"…","schema":"public","sslMode":"prefer"}
```

## 2. BDD Scenarios

### SC-01: Project Detection on Open Folder
```
Given a folder with dbsp.settings.json exists
When I open this folder via File > Open Folder
Then the app transitions to project mode
And a project entry is created in app.sqlite recent_projects
And project-specific data.sqlite is created in $APPCONFIG/projects/<project-name>/
```

### SC-02: Standalone Mode (No Project)
```
Given no folder is open (standalone mode)
When I execute a query
Then the query is saved to $APPCONFIG/default/data.sqlite query_history
And IPC logs go to $APPCONFIG/default/data.sqlite ipc_logs
And app-level logs go to $APPCONFIG/app.sqlite app_logs
```

### SC-03: Migration from localStorage
```
Given existing query history in localStorage (dbsp-history)
And existing connection profiles in localStorage (dbsp-connections)
When the app starts for the first time after upgrade
Then localStorage history entries are migrated to default/data.sqlite
And localStorage connection profiles are migrated to default/data.sqlite
And a _meta entry 'migration_complete' = 'true' is set
And localStorage data is preserved (not deleted) as fallback
```

### SC-04: Idempotent Migration
```
Given migration was partially completed (crash mid-migration)
When the app restarts
Then migration runs again from the beginning
And existing SQLite entries are replaced (INSERT OR REPLACE)
And migration completes successfully this time
```

### SC-05: New Project Wizard (Sidebar Steps)
```
Given I am in standalone mode or any mode
When I click File > New Project
Then a wizard dialog opens with a sidebar showing 4 steps:
  Step 1 — Introduction: brief explanation of project mode
  Step 2 — Name: project name + folder location (browse)
  Step 3 — Connections: manage project connections (multiple environments)
    - Existing connection auto-detected and pre-added if user is already connected
    - Each connection opens the reusable ConnectionDialog (same as standalone connection)
    - Each connection has an "environment" label (defaults to connection name/label)
    - User can add 0..N connections (0 = NQL plan-only, no results)
    - If 0 connections: a warning explains "only NQL plan execution available, results tab disabled"
  Step 4 — Options: generate schema.ts? (checkbox, needs ≥1 connection)
When I complete the wizard
Then dbsp.settings.json is created in the chosen folder
And the app transitions to project mode for this folder
And a recent_projects entry is created in app.sqlite
And all wizard connections are saved to data.sqlite connection_profiles with their environment labels
```

### SC-06: Convert Ad-hoc to Project
```
Given I am connected to a database in standalone mode
When I click "Save as Project" button
Then the New Project wizard opens (same sidebar dialog)
And Step 3 (Connections) is pre-populated with the current active connection
And the environment label defaults to the connection's name/label
When I complete the wizard
Then the current connection is saved to the new project's data.sqlite connection_profiles
And dbsp.settings.json is created
And the app transitions to project mode
```

### SC-07: Reverse Engineering (schema.ts generation)
```
Given I am in the New Project wizard at Step 4 (Options)
And "Generate schema.ts" is checked
And at least one connection was added in Step 3
When I click "Create Project"
Then the sidecar introspects the database
And generates a schema.ts file in the project folder
And the schema.ts does NOT contain credentials
And the schema tree refreshes with the introspected schema
```

### SC-08: Schema.ts Editor
```
Given I am in project mode with a schema.ts file
When I click "Edit Schema" in the schema tree header
Then a new Monaco tab opens with the schema.ts content
And the tab shows TypeScript syntax highlighting
When I edit and save the file
Then a file watcher detects the change (debounced 500ms)
And the sidecar reloads the schema
And the schema tree refreshes
```

### SC-09: Schema.ts Parse Error
```
Given I am editing schema.ts in the Monaco editor
When I save with a syntax error
Then a toast shows "Schema parse error: [details]"
And the schema tree keeps the last valid schema
And the editor shows the error (red underline if possible)
```

### SC-10: File Menu — New NQL File
```
Given the app is running
When I click File > New NQL File
Then a new editor tab opens in NQL mode
And the tab is named "Untitled.nql" (or next available number)
```

### SC-11: File Menu — Project Items
```
Given the File menu is open
Then I see: New Project..., Open Project... (alias for Open Folder), Recent Projects submenu
And Recent Projects shows up to 10 most recently opened projects
When I click a recent project
Then the app opens that folder and transitions to project mode
```

### SC-12: Recent Projects — Project Removed
```
Given a project in Recent Projects has been deleted from disk
When I click on it
Then a toast shows "Project folder not found: [path]"
And the entry is removed from Recent Projects
```

### SC-13: App Logs Global
```
Given the app is running
When the sidecar emits stderr output
Then it is logged to $APPCONFIG/app.sqlite app_logs (source='sidecar')
When an app-level event occurs (project opened, settings changed)
Then it is logged to $APPCONFIG/app.sqlite app_logs (source='app')
```

### SC-14: IPC Logs Scoped
```
Given I am in project mode and connected
When an IPC request/response occurs
Then it is logged to the project's data.sqlite ipc_logs
And the log includes the method name and duration
And the LogPanel shows these logs with "ipc" source badge
```

### SC-15: Log Panel Split — Two Surfaces
```
Given I am in project mode
Then the bottom panel "Logs" tab shows project-scoped logs (ipc_logs from data.sqlite)
And the status bar "+" button (bottom-right) opens an app-level log popover
And the app-level log popover shows global logs (app.sqlite: sidecar stderr, app events)
When I am in standalone mode
Then the bottom panel "Logs" tab shows default/data.sqlite ipc_logs
And the status bar "+" still provides access to app-level logs
```

### SC-16: Connection Profiles in Project (Multi-Environment)
```
Given I am in project mode
When I create a new connection via Connection > New Connection
Then the profile is saved to the project's data.sqlite connection_profiles
And the connection config is stored as JSON in the `config` column (engine-agnostic)
And an environment label is assigned (defaults to connection name)
And it appears in the connection dropdown grouped by environment
When I reopen this project later
Then the connection profiles are loaded from data.sqlite
And the active environment is restored
```

### SC-17: Query History Search in Project
```
Given I am in project mode with query history
When I open the History panel and search "SELECT"
Then only queries matching "SELECT" from THIS project are shown
And queries from other projects or standalone are not shown
```

### SC-18: Startup — Project Recovery
```
Given I was working in project mode and closed the app
When I reopen the app
Then it opens in standalone mode (clean start)
And the welcome screen shows Recent Projects for quick access
```

### SC-19: Open Folder Without Project Marker
```
Given I open a folder that does NOT contain dbsp.settings.json
Then the app stays in standalone mode
And a subtle banner suggests "Create project from this folder?"
And all data goes to default/data.sqlite
```

### SC-20: Switch Project (Close + Open)
```
Given I am in project mode with project A
When I open project B via File > Open Project
Then project A's DB connections are flushed and closed
And file watchers for project A are stopped
And project B's data.sqlite is opened
And recent_projects is updated for both A (last_opened) and B
```

### SC-21: Corrupt Database Recovery
```
Given a project's data.sqlite is corrupted (0 bytes or invalid header)
When the app opens this project
Then the corrupt file is renamed to data.sqlite.corrupt
And a fresh data.sqlite is created with empty tables
And a toast warns "Database was corrupted and has been reset"
```

### SC-22: Wizard Error Handling
```
Given I am in the New Project wizard at Step 3 (Connections)
When the connection test fails (wrong host, auth error, timeout)
Then the wizard shows the error inline without closing
And I can edit the connection and retry
When I try to create a project in a read-only folder
Then a toast shows "Cannot write to folder: [path]"
And the wizard stays open for correction
```

### SC-23: IPC Log Redaction
```
Given an IPC request contains sensitive fields (password, secret, token)
When it is logged to ipc_logs
Then sensitive values are replaced with "[REDACTED]"
And the log entry is otherwise complete (method, duration, status)
```

### SC-24: Project Without Connections — NQL Plan-Only Mode
```
Given I created a project with 0 connections (skipped Step 3)
When I am in project mode
Then the "Results" tab in the bottom panel is disabled with tooltip "No connection — plan-only mode"
And NQL queries can be executed for plan inspection (no DB roundtrip)
And SQL execution shows a toast "No connection configured — use File > Project Settings to add one"
When I later add a connection via settings
Then the Results tab becomes available
```

## 5. Migration Strategy

### Atomic Migration (on first startup)

Simplified from original 3-phase plan per LLM review — dual-write adds complexity without value for a desktop app.

1. On startup, check `_meta.migration_complete` in default/data.sqlite
2. If not set and localStorage has data (`dbsp-history`, `dbsp-connections`):
   a. Migrate all history entries to `query_history` (INSERT OR REPLACE by UUID)
   b. Migrate all connection profiles to `connection_profiles` (INSERT OR REPLACE by UUID)
   c. Set `_meta.migration_complete = 'true'`
   d. Preserve localStorage as fallback (do NOT delete)
3. If migration fails mid-way (crash): on next startup, re-run from step 2 (idempotent via INSERT OR REPLACE)
4. Skip invalid localStorage entries (malformed JSON) with warning count in toast
5. After migration, all reads/writes go to SQLite exclusively
6. localStorage retained only for user-settings (small key-value, Zustand persist)

## 6. Non-Functional Requirements

| NFR | Target |
|-----|--------|
| Startup time | < 500ms additional for SQLite init |
| Query history search | < 100ms for 10K entries |
| Migration (500 entries) | < 2s |
| Schema.ts reload | < 1s after save |
| Memory usage | No increase beyond SQLite engine overhead |
